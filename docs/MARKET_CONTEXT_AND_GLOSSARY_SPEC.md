# Market Morning — 現在のマーケット概要・用語解説 仕様 v1

## 1. 目的
日次ニュースを追えていない利用者や金融初心者でも、「なぜ今この相場環境なのか」を数分で把握できる常設レイヤーを追加する。日次モーニングレポートを置き換えず、時間軸を補完する。

- 長期〜中期：現在のマーケット環境（数か月〜年初来）
- 短期：日次Market Morning
- 補助：初心者向け用語解説

## 2. 「今のマーケット」セクション
世界市場ページ上部のQUICK VIEW付近に、日次ニュースとは独立した入口を設ける。

### 必須表示
1. **いまの市場を一言で** — 現在の主要テーマを初心者向けに2〜4文で説明。
2. **ここまでの流れ** — 原則直近3〜6か月。年初からの流れが重要なら年初来。重要転換点を3〜6件、「事実 → 市場への影響」で時系列表示。
3. **今、市場が見ていること** — 金利、為替、景気、政策、地政学、AI/半導体、中国、商品等から重要なものだけ。
4. **日本株へのつながり** — 海外要因 → 為替/金利/商品 → 日本株/業種、の因果を簡潔に説明。
5. **暮らしへの影響** — 住宅ローン、預金金利、物価、ガソリン・電気、輸入品、税制等から関連するものだけ。市場要因と制度・税制変更を混同せず、税制・制度は施行日、制度内容、公式根拠を確認する。
6. **この見方が変わる条件** — 現在の環境認識を修正する具体的な政策、経済指標、価格条件等。

## 3. 更新ルール
- 原則週1回。
- 中央銀行の政策転換、重大な政策変更、地政学ショック、大幅な市場レジーム変化などがあれば臨時更新。
- 日次レポート生成時に毎回AI/APIを追加で呼ばない。
- 日次ニュースの転載・羅列にしない。
- 更新日時と対象期間を明示する。

## 4. 品質ルール
既存Market Morning品質ゲートを適用し、さらに以下を確認する。
- 初心者向けに単純化しても因果関係を断定し過ぎていないか。
- 「同時に起きた」ことを「原因」と誤記していないか。
- 市場要因、金融政策、税制・制度要因を分離しているか。
- 生活への影響は、直接影響・間接影響・可能性を区別しているか。
- 未確定政策は確定事項として記載しない。
- 数か月前の説明が現在も有効かを更新時に再検証する。

## 5. データ構造
新規 `data/market-context.json` を基本とし、日次 `report.json` から分離する。

想定フィールド：
- `updated_at`, `period_start`, `period_end`, `headline`, `summary`
- `timeline[]` — date / title / fact / market_impact
- `current_drivers[]` — title / explanation / japan_impact
- `daily_life_impacts[]` — topic / mechanism / impact / evidence_type
- `scenario_change_conditions[]`
- `sources[]`

履歴保存は日次ではなく、更新時スナップショットを基本とする。

## 6. UI方針
- 通常の日次レポートより「背景を理解する」見た目にする。
- 初期表示は要約のみ。詳細はアコーディオン等で展開し、スマホ縦長化を抑える。
- 「ここまでの流れ」は短い縦タイムラインを基本とする。
- 「暮らしへの影響」は独立カード。
- 日次ニュースとの境界を明示し、古いニュース一覧に見せない。
- 「最終更新」「対象期間」を常時表示する。

## 7. 用語解説
固定辞書方式とし、AI/APIを表示時に呼ばない。新規 `data/glossary.json` を基本とする。

各用語：
- `term`
- `short` — 1〜2文
- `why_it_matters` — Market Morningで何を見るための用語か
- `aliases[]`

初期候補：DXY、SOX、NASDAQ100、Russell2000、VIX、米2年債、米10年債、イールドカーブ、利下げ織り込み、タカ派、ハト派、PER、EPS、Breadth、WTI、Brent、LME、SHFE、COMEX、TC/RC、ドル円、円高、円安、先物、TOPIX。

本文中の対象語に小さなⓘ等を付け、タップ/クリックで短い説明を表示する。モバイル最優先でホバー必須にはしない。

## 8. 負荷方針
- market-context：週次中心の静的JSON。
- glossary：固定JSON。
- 表示はクライアント側で既存JSONと併読。
- 用語表示のための外部API/AI呼び出しは禁止。
- 日次市場データ取得処理への追加負荷を原則発生させない。

## 9. 実装順
1. 本仕様を確定。
2. `market-context.schema.json` / `glossary.schema.json` を設計。
3. 初回 `market-context.json` を最新情報のWeb調査に基づき作成。
4. 初回 `glossary.json` を作成。
5. 世界市場ページへ「今のマーケット」を実装。
6. 重要語から用語ポップアップを段階導入。
7. モバイル表示確認。
8. Schema・内容・出典・Vercel本番表示まで検証。
9. Webサイト仕様書の現在状態を更新。

## 10. 完了条件
- 初心者が日次ニュースを読まなくても現在の主要市場テーマを理解できる。
- 数か月の流れと「今日」の分析がつながる。
- 日本株への波及と暮らしへの影響が因果で説明される。
- 日次処理のAI/API負荷を実質的に増やさない。
- 用語解説はスマホでタップ可能。
- 既存の日次レポート・日本株ページ・履歴機能を壊さない。
- GitHub品質ゲートとVercel本番表示確認を通過する。
