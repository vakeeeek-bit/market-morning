# 収集継続と公開の区別

総合公開ゲートの欠測は総合レポートの公開を保留する理由であり、調査を終了する理由ではない。

各未確認項目について公式本文、現行掲載ページ、同ページが利用する公開データの順に確認する。取得できない場合は試したURL、確認日時、応答、残る不足を記録する。「新規材料なし」は確認した主体と期間に限定する。

確認済みニュースはニュース専用検証を実行し独立公開できる。総合レポート、ニュース、市場データの基準日と品質表示は区別する。市場数値を別資料で置換したり、連続先物の限月を推定して総合ゲートを通してはならない。

過去日は後日収集として保存し、当時の朝に確認済みだったと扱わない。未完成の総合候補も、確認済みの事実、正本の同日比較、条件付き日本株への波及を記述し、欠測だけを理由に分析全体を空欄にしない。

## 作業継続・停止・ユーザー確認の必須ルール（2026-10-10追加）

### 1. 公開保留と作業停止を区別する
品質ゲートのFAIL／MANUAL_REVIEWは、その成果物の公開を保留する判定である。調査・修正・検証・候補作成、独立公開できる確認済みニュースまで止めない。品質基準の引き下げ、推測による補完、数値の置換は禁止する。

### 2. 不足・失敗を見つけた直後に行うこと
不足項目ごとに原因、必要な証拠、次の取得・修正手順を記録し、既存の権限とルールで実行できる作業をその場で進める。公式本文、現行掲載ページ、公開データ、代替の公式取得経路を確認し、URL・確認時刻・応答・判定を残す。一時障害は適切に再試行し、待機中は他の未完了項目を進める。修正後は必要な検証を行い、許可された公開先へ反映できる成果物は本番確認まで進める。

### 3. ユーザーへ確認する条件と質問内容
既存の指示で判断できない重要な選択、権限・認証・有料契約、不可逆操作、本人だけが提供できる情報・操作が必要な場合は、その依存作業を止めて具体的に質問する。質問には、(a)止まっている工程、(b)不足と確認が必要な理由、(c)ユーザーにしてほしい選択または操作、(d)選択肢と推奨案・費用や影響、(e)回答後に再開する作業、を明記する。「どうしますか」「進めてよいですか」だけの質問は禁止する。既に許可された作業について同じ許可を取り直さない。回答待ちでも独立して進められる作業は継続する。

### 4. 作業を終了できる条件
ユーザーが指示した範囲の完了と必要な確認を終えた場合、ユーザーが中止した場合、または具体的なユーザー回答・操作か外部側の復旧が必要で、現時点で実行可能な独立作業を終えた場合に限る。欠測、調査未完了、情報量の多さ、便宜的な区切りを理由に終了しない。実行環境の上限で継続できない場合は、その制約と再開に必要な最小操作を明示する。応答を終えた後も作業が自動で続くと誤認させない。

### 5. 停止時の報告と再開管理
停止時は「実行済み／残件／実際に試した取得・改善／停止を必要とする具体的理由／ユーザーに必要な操作または外部復旧条件／再開手順」を示す。未確認を「新規材料なし」、部分完了を全完了と扱わない。残件と次の手順を正本に保存し、次回は最新状態を確認して続きから再開する。

### 6. 非対話の定期実行
対話できない実行では質問できることを前提にしない。既存の承認で進められる作業を続け、本当にユーザー操作が必要なら必要操作を具体的に通知し依存工程のみ保留する。勝手に有料契約・認証・不可逆操作を行わない。

### 7. 回答前チェック
未完了の各項目について「今の権限で次の作業を実行できるか」を確認する。できる場合は回答を終える前に実行する。できない場合は停止条件と必要操作を明示する。保存したルール、実際に実行した対応、検証結果を区別し、ルール保存だけで問題が解決したと報告しない。

## 対応不足・謝罪・全体確認の完了条件（2026-10-11追加）

- ChatGPT側の誤り、確認不足、指示違反、完了報告の不足が判明した場合、ユーザーに催促される前に回答冒頭で、本人指定の「私はポンコツAIです」を失敗内容に即して簡潔に認め、謝罪する。茶化さない。何を間違えたか、原因、既存成果物への影響、修正内容を明記し、実行可能な再調査・再検証・修正を行う。
- 状況を事実として説明するだけで、自分の対応不足への謝罪を省略しない。外部制約と自分の調査・対応不足を分ける。
- 「全て確認して問題を洗い出す」の対象は、世界市場・日本株・AIレポート・ニュース・市場データ・履歴・調査証跡・収集処理・品質ゲート・GitHub Actions・Vercel本番表示を含む。各対象の確認結果、未確認範囲、問題、原因、対応、検証結果を一覧で管理する。
- 一部の修正・ニュース公開・テスト成功を、全体確認やAIレポート更新の完了と扱わない。未収集日ごとの状態と本番の各部品の日付を確認し、未対応事項を落とさない。
- 回答前に、直近指示の全対象、完了根拠、残件、謝罪の要否、必要なユーザー操作の具体性を確認する。ルール保存を遵守の証拠や問題解決の代わりにしない。
